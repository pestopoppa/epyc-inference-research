## AK-H-TACPU-L3L2-1 -- L2 q-group inversion and per-CCD L3 blocking for CPU flash attention
Source: intake-2959#record (TACPU, dive K4). Verdict: TRANSFERS-WITH-CHANGES.
**Mechanism:** `ggml_compute_forward_flash_attn_ext_tiled` (`ops.cpp:9916-10232`) loops over all KV for each Q tile of 64 and re-packs K per Q tile, with no K/V reuse across Q tiles, no L3 chunking and no L2 q-group loop. TACPU's piece that gave the most on its Xeon was the L2 q-group inversion (1.66x in its ablation; the stack, not one piece, gives the 2.01x headline, and that figure is 128K on an AMX Xeon with llama.cpp never a baseline). On Zen 5 size the group for 1 MB L2 and fp32 K tiles, and size the L3 K/V chunk per CCD (32 MB per 8-core CCD, not one shared L3), pinning the threads of a chunk to one CCD. The AMX/softmax overlap has no Zen 5 counterpart; leave it out.
**Target:** CPU served roles on a long-context prefill (>= 32K tokens). CPU flash-attn tiled is 3.47-5.88% of cycles in the existing profiles at p8192; the share at depth is unmeasured.
**Expected gain [inferred]:** unbounded by data; a few percent of long-prefill wall clock at most while attention stays a few percent of cycles. Confidence low.
**Falsifier:** measure the flash-attention share of prefill first (zero compute, existing profiles); share under 5% at 32K or the op-level kernel not beating the tiled path by the A/A p95 -> close. Row-exactness is already lost above 256 KV (INF-70 note), so compare by KLD, not bit-identity.
**Gate:** CPU W5 4.15% end-to-end plus the KLD gate. Effort: M (loop-nest restructure plus CCD-aware thread grouping).

## AK-H-FA-LONGEST-FIRST-1 -- run the CPU flash-attention row chunks longest-first
Source: intake-2959#record (dive K4; cost-sorted queue, Table 2). Verdict: TRANSFERS-WITH-CHANGES.
**Mechanism:** the row chunking (`ops.cpp:10574-10620`, 4 chunks per thread, atomic fetch-add at `ggml-cpu.c:754`) is dynamic but consumed in ascending row order. Rows are head-major then position, so the cheap early positions run first and the expensive late causal positions last: the worst order for the tail effect. Reverse the chunk order per head (or sort rows by exact non-masked KV tile count, LPT). TACPU measured 1.03-1.29x of a cost-sorted queue against FIFO on a homogeneous Xeon; its 2.45x is a hybrid-core effect and does not apply.
**Target:** the same long-prefill CPU case as AK-H-TACPU-L3L2-1; independent of it (a one-line order change).
**Expected gain [inferred]:** the tail wave of a causal prefill; bounded by the flash-attention share of prefill. Confidence low.
**Falsifier:** the flash-attention share of prefill below 5% at 32K, or a thread-time spread (max/mean) below 1.1 on the existing order -> no tail to recover, close.
**Gate:** bit-identical output (order only); CPU W5 4.15% end-to-end. Effort: S.

## AK-H-FA-NPS4-DISPATCH-1 -- probe: shared dispatcher queue versus static split under NPS4
Source: intake-2959#record (dive K4). Verdict: UNKNOWN-NEEDS-PROBE (the paper tested SNC-2 only).
**Mechanism:** a shared atomic queue ignores NUMA locality of K/V pages. Our launches use `numactl --interleave`, so K/V is spread and locality should be moot, but nothing measured it on this host. Probe only: A/B the dynamic chunking against a static split on one CPU role at NPS4, interleaved, at 32K+. UNVERIFIED: that no served launcher passes `--numa` (which would disable dynamic chunking at `ops.cpp:10577-10589`).
**Expected gain [inferred]:** 0 expected; this decides whether AK-H-FA-LONGEST-FIRST-1 may rely on the dynamic queue. Confidence low.
**Falsifier:** dynamic versus static within the A/A band -> the probe closes with a null and the locality question is retired.
**Gate:** probe, no keep. Effort: S.

## AK-H-DPP-SCAN-CUMSUM-1 -- HIP DPP wave64 prefix scan, held for a CUMSUM consumer
Source: intake-2962#record (llama.cpp PR #32867, dive K3). Verdict: TRANSFERS-WITH-CHANGES, no served consumer.
**Mechanism:** the PR's DPP `warp_prefix_inclusive_sum` (row_shr 1,2,4,8, then row_bcast:15 mask 0xa and row_bcast:31 mask 0xc) is correct for wave64 and gfx90a takes the row_bcast branch (CDNA2). Its one caller is `cumsum.cu`; the fused GDN ops we serve emit no CUMSUM, and the only other producer is backend sampling over the vocabulary. The PR's 15-19% is on MI50 (gfx906) and RDNA4, not gfx90a. The DPP `warp_reduce_sum` half is a separate screen (stock GDN still uses `shfl_xor`).
**Trigger:** backend sampling turned on for a GPU role, or a graph that emits CUMSUM on gfx90a. Then time one CUMSUM [vocab,1] op on gfx90a before judging the PR.
**Expected gain [inferred]:** 0 today; about 88 us per call at ne0=200000 on MI50 if a consumer appears.
**Falsifier:** CUMSUM share of the step below 1% on gfx90a, or gain under the A/A p95 at the op level -> close. Effort: S (cherry-pick the scan behind the CDNA branch).

## AK-H-HADAMARD-GRAN-1 -- Hadamard rotation granularity for Q8 / MXFP4 weights
Source: intake-2957#record (Shifter Quantization, dive K2) and intake-2961#record (MXFP4 PTQ, PDF-only partial read). Verdict: UNKNOWN-NEEDS-PROBE.
**Mechanism:** SQ8 is plain per-output-channel INT8 after a signed H512 rotation, 8.0 bits per weight against Q8_0's 8.5, at most about 6% fewer weight bytes with 16-byte-aligned rows and no scale gather. Whether per-channel scales after a rotation keep Q8_0's per-32 quality is unknown (the paper's KL win is against per-tensor FP8). Offline probe: rotation block size (H32 / H128 / H512) against Q8_0 per-32 scales on real 27B rows, measuring weight and output error and dKLD if cheap. No kernel work. The runtime half (an online H512 butterfly before every projection, fusable with the activation quantize) is high effort and opens only on an offline pass. Shares its arm with QUANT-ROT-1.
**Expected gain [inferred]:** up to ~6% of decode weight bytes on the Q8_0 27B if quality-viable. Confidence low.
**Falsifier:** per-channel INT8 after rotation does worse than Q8_0 per-32 on dKLD by more than 0.003 at every block size -> close the byte lever.
**Gate:** offline probe first; then 27B KLD <= 0.003, |dPPL| <= 0.5%. Effort: S offline, H online.

## AK-H-OAS-E8M0-ROUNDUP-1 -- round-up E8M0 scale rule for a BF16-to-MXFP4 requant
Source: intake-2978#record (Overflow-Aware Scaling) and intake-2961#record (Midmax; the same threshold under another name, cite one rule). Verdict: TRANSFERS (quantizer side only).
**Mechanism:** `quantize_row_mxfp4_ref` uses plain floor (`ggml-quants.c:368`, `e = floor(log2f(amax)) - 2 + 127`). The rule: if the floor-scaled block max exceeds 7, take the next exponent. About 3 lines in an experimental quantizer; dequant is unchanged, so no kernel change on either device. The papers' gains are W4A4 with no weight-only ablation and no KLD, so treat them as direction, not evidence. The one served MXFP4 model is a lossless repack of native FP4 experts and never calls the scale rule, so it cannot change.
**Trigger:** a BF16-to-MXFP4 requant is queued. Then A/B round-up against floor, judged by KLD.
**Expected gain [inferred]:** a KLD reduction on a requanted model; 0 on the current lineup. Confidence low.
**Falsifier:** KLD not lower than floor by the noise of the KLD estimate on the requant -> close.
**Gate:** KLD A/B on the requanted model. Effort: S.

## AK-H-MMQ-ORDER-TEMPLATE-1 -- probe: compile-time order template versus runtime branch in the CDNA MMQ stream-k path
Source: intake-2956#record (llama.cpp PR #32921, dive K1). Verdict: UNKNOWN-NEEDS-PROBE, moot today.
**Mechanism:** the PR's reviewer exchange reports a runtime branch on the tile order (`ntizw.z != 0` in the fixup kernel) costing up to 8%, with no numbers in the thread (the author: "there was a regression in doing that"). A kernel-argument-uniform branch is a scalar branch on CDNA, but the 512-thread occupancy-1 MMQ cell is register-tight, so the cost, if any, is in per-tile index decode and register allocation. Probe: one extra template instance per (type, J=64) against the runtime branch, judged on wall clock, not L2 hit rate. Dormant: served np4 verify at M=36 has one column tile per tensor, so the new order equals the old, and Q8_0 above 128 columns goes to rocBLAS.
**Trigger:** Q8_0 dense prefill is ever routed to MMQ on gfx90a. Then port the column-outer order behind a CDNA J=64 gate first, and run this probe on that kernel.
**Expected gain [inferred]:** 0 today. Confidence low.
**Falsifier:** template and branch variants within the A/A p95 on the 512-thread MMQ cell -> keep the branch, close.
**Gate:** wall clock same-window A/A; bit-identical. Effort: S once the port exists.

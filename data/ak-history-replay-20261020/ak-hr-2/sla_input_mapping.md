## (d) Does the window separate sealed-valid non-improvement from inconclusive failure?
Partially, by row label only, never by section.
- Valid-comparison class: `measured_null`, `regression` (plus kept/keep_candidate). `dispatch_guard.ANSWER_STATUSES` = kept, keep_candidate, confirm_vetoed, measured_null, regression (loop/dispatch_guard.py:14-15); serial_scheduling `VALID_COMPARISONS` (loop/serial_scheduling.py:15-16).
- Not-a-measurement classes: `INVALID_OUTCOMES` (serial_scheduling.py:17-26, includes refused_at_formation, patch_rounds_exhausted, authoring_failed, runtime_refused) and `FAILED_OUTCOMES` = bench_failed, lane_error, planner_transient, authoring_harness_failure (serial_scheduling.py:27-28).
- In the planner window: recall merit ranks measured_null/regression 5.0 vs bench_failed 1.0, lane_error 0.5, planner_transient 0.25 (E:225-243) but only when `--rank-prior-experiments` is on; otherwise recall is newest-first and harness rows flood the 12-row window (E comment L204-214; R:1781-1784, `_with_pinned_history` R:1805-1819 pins only kept/keep_candidate/abstained/measured_null).
- Rendering: one undifferentiated `## Already tried` list printing raw `status` (A:2857). `abstained` is pinned as if a null (A:2883-2886, family-pinned with measured_null); `abstained`, `refused_at_formation`, `screened_out`, `authoring_refused`, `hypothesis_retired` count as TERMINAL failures toward the exhausted-family trigger alongside measured_null/regression (A:2681-2682); stagnation set adds `runtime_refused`, `abstained` (A:2730-2731). So inconclusive/refusal rows are counted as "resolved failures" in `DIMINISHING-RETURNS ESCAPE`, whereas planner_transient, lane_error, bench_failed, patch_rounds_exhausted, scope_blocked, gate_refused do not enter either trigger (not in the sets at A:2681, A:2730) and appear only in the raw list.
- The only validity qualifier shown is `[mechanism claim: verified|hypothesis]` (A:2856-2858, claims.py:60-74) and `[STALE EPOCH ...]` (A:2851); neither says "comparison sealed-valid".
- Gap: no payload `comparison` presence check feeds a label; `measured_null` is trusted as the sealed-valid marker (writers outside actors.py not audited here beyond status-set definitions). do_not_repeat.py:94-98 shows the intended doctrine (a voided/`invalid` attempt folds to CONFOUNDED_RESULT, advisory, "no result"), but that class never reaches the prompt.

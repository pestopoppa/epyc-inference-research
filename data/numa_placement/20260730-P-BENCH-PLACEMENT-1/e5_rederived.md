## 1. What is being recomputed, and the one thing that must not be conflated

**Old field** `aggregate_predicted_tps` = `predicted_tokens_total / wall_seconds`.
A WALL-CLOCK rate. `wall_seconds` spans the whole cell — model load, warmup, prefill, queueing, idle gaps — so it reads systematically low and is not comparable to llama.cpp's `predicted_per_second` or to `llama-bench` tg. (Verified: for `qwen36_q8_0-C1-np1`, 3758 / 334.6596 = 11.2293 = the persisted value exactly.)

**New field** `aggregate_decode_tps` = `sum(predicted_n) / sum(predicted_ms/1000)` over successful requests, from llama.cpp's verbatim per-request `timings` block in `requests.jsonl`. Tokens decoded over time actually spent decoding.

Exclusion rule (applied identically to numerator and denominator, matching `server_numa_np_sweep.py:1322-1334`): a successful request is skipped when its `timings` block is missing, when `predicted_n`/`predicted_ms` are absent, when either is non-numeric or a bool, or when either is `<= 0`.

> ### The denominators are different. Do not read `new/old` as a bug magnitude.
>
> `sum(predicted_ms)` is a sum of **overlapping** wall intervals — one per slot. (Confirmed on the data: for request 0 of `qwen36_q8_0-C1-np1`, `predicted_ms` = 7663.5 ms and `end_s - first_token_s` = 7664 ms. `predicted_ms` IS that slot's elapsed generation window.) So with `T` concurrent streams the denominator counts up to `T` seconds of slot time per elapsed second, and `aggregate_decode_tps` is the token-weighted mean **PER-SLOT** decode rate.
>
> `aggregate_predicted_tps` divides by **elapsed** seconds, so it is a **SYSTEM-WIDE** rate.
>
> Dividing one by the other at `T=32` produces ~0.07x and means nothing. To measure the metric bug you must compare like with like. This report therefore also computes a system-wide decode rate on the same footing as the old field:
>
> **`system_decode_tps` = `sum(predicted_n)` / |union of all `[first_token_s, end_s]` intervals|** — total tokens decoded divided by elapsed wall time during which *any* slot was decoding. Same numerator as the old field, same kind of denominator, minus load/prefill/idle.

## 2. NUMA classification — explicit mapping logic

Host is NPS4. Topology read live from `lscpu` and hard-coded in the script:

```
node0 = 0-23,96-119     node1 = 24-47,120-143
node2 = 48-71,144-167   node3 = 72-95,168-191
```

96 physical cores are `0-95`; `96-191` are their SMT siblings (core *i* pairs with thread *i+96*), so each node owns 24 cores plus those 24 siblings.

**Per instance**, from that instance's `instances[].cpu_list` in the persisted cell record — the exact string handed to `taskset -c`:

1. Expand the cpuset string to a set of logical CPU ids.
2. Map every id to its NPS4 node with the table above.
3. Let `nodes` be the resulting distinct node set:
   * `len(nodes) == 1`  ->  **node-aligned**
   * `nodes == {0,1,2,3}`  ->  **full-machine**
   * otherwise (2 or 3 nodes)  ->  **straddling**
4. `exact_node_match`: the cpuset equals the union of the full node sets it touches (no partial node). **TRUE for every E5 cell** — no cell uses a ragged cpuset, so step 3 is unambiguous.

A multi-instance cell takes the worst class: any straddling instance makes the cell straddling.

Concretely, the four shapes in this campaign:

| shape | instances | cpuset(s) | threads | nodes | class |
|---|---:|---|---:|---|---|
| C1 (qwen36, 80b) | 1 | `0-47,96-143` | 96 | N0+N1 | **straddling** |
| C1 (gemma) | 1 | `0-95` | 96 | N0+N1+N2+N3 | **full-machine** |
| C1b | 2 | `0-47,96-143` / `48-95,144-191` | 96 each | N0+N1 / N2+N3 | **straddling** |

### How the numactl flag was determined

`server_numa_np_sweep.py::instance_launch_prefix` (lines 383-394) builds the launch prefix as:

```python
cmd = ["taskset", "-c", inst.cpu_list]
if inst.numactl_policy == "interleave=all":
    cmd += ["numactl", "--interleave=all"]
elif inst.numactl_policy != "none":
    raise RuntimeError(...)
```

so `instances[].numactl_policy` in the persisted record is a faithful record of whether the launch command carried a memory-policy flag. The value is validated at manifest-load time against exactly `{"none", "interleave=all"}` (line 272), and **`none` means no `numactl` binary in the command line at all**. Across the entire E5 corpus only those two values occur — **no cell anywhere uses `--membind`**.

| shape | numactl_policy | launch prefix |
|---|---|---|
| C1 (qwen36, 80b) | `none` | `taskset -c 0-47,96-143 llama-server ...` |
| C1 (gemma) | `interleave=all` | `taskset -c 0-95 numactl --interleave=all llama-server ...` |
| C1b / C2 / C3 | `none` | `taskset -c <quarter|half> llama-server ...` |

**Defect-B criterion (as briefed):** a multi-node cpuset (`straddling` or `full-machine`) launched with `numactl_policy = none` is first-touch placed and therefore confounded. A single-node cpuset, or a multi-node cpuset that did carry `--interleave=all`, is clean.

By that criterion: **18 clean, 13 confounded**. Section 5 shows why that criterion is not sufficient here.

## 5. The NUMA defect is worse than the cpuset shape suggests

The briefed model of defect B is that node-aligned quarter cpusets (C2, C3) are node-local and therefore unaffected. **The persisted evidence contradicts that**, and the contradiction is decisive for salvageability.

### The measurement

Every cell has an affinity artifact (`<run>/affinity/<cell_id>.json`). Its `instances[].memory_placement.pages_by_node` is produced by `epyc-orchestrator/scripts/server/affinity_preflight.py` (`_summarize_numa_maps`, lines 161-221): it reads `/proc/<pid>/numa_maps` and sums the per-node page counts of every mapping line carrying `file=<...>.gguf`. That is the **physical NUMA placement of the model weights**, measured live on the running server — not an inference from the cpuset.

`local_fraction` = pages sitting on that instance's own expected node(s) / total pages.

### What it shows

The GGUF is mmap'd **shared**. All instances of a model map the *same physical pages*, so `pages_by_node` is byte-identical across every instance of a cell and across every cell in a run — the weights are placed **once**, by whichever process first faulted them in, and every later cell in the run inherits that placement from the page cache. `numa_balancing = 0` (per run attestation), so nothing migrates them afterwards.

Cell execution order makes the mechanism unambiguous:

| run | first cell executed | its cpuset | its numactl | resulting placement of the shared GGUF | inherited by |
|---|---|---|---|---|---|
| `e5-w1-qwen36` | `qwen36_q8_0-C1-np1` @ 15:53:19 | `0-47,96-143` (N0+N1) | `none` | **100% on N0** (9,226,101 / 9,226,101 pages, ~35 GB) | all 11 cells |
| `e5-w4-80b` | `qwen3_next_80b-C1-np1` @ 17:06:39 | `0-47,96-143` (N0+N1) | `none` | **100% on N0** (11,817,629 / 11,817,629 pages, ~45 GB) | all 12 cells |
| `e5-w2-gemma` | `gemma4...-C1-np1` @ 18:33:48 | `0-95` (all nodes) | `interleave=all` | **evenly interleaved** (N0 1,051,407 / N1 1,051,414 / N2 1,051,403 / N3 1,051,392 — 25.00% each) | all 8 cells |

Two textbook signatures, exactly as predicted: first-touch concentration on the lowest node of the loader's cpuset, versus a perfectly even 4-way split from `--interleave=all`.

C3 has exactly one local instance out of four. The gemma quarters each get 25% local, which is the *symmetric* interleaved case rather than the intended node-local one.

### Independent corroboration from the timing data

If the placement measurement is real, per-instance decode rates in a C3 cell should fall with NUMA distance from N0. At np=1 (least queueing noise) they do, monotonically; the gemma control, with symmetric interleaved pages, shows no such gradient:

| cell | N0 inst | N1 inst | N2 inst | N3 inst | pattern |
|---|---:|---:|---:|---:|---|
| `qwen36_q8_0-C3-np1` | 3.32 | 3.13 | 2.22 | 2.10 | monotone decline, 1.58x local:far |
| `qwen3_next_80b-C3-np1` | 3.02 | 2.07 | 1.62 | 0.96 | monotone decline, 3.15x local:far |
| `gemma4_26b_a4b_q4km_mtp-C3-np1` | 10.42 | 13.17 | 14.89 | 12.16 | flat (interleaved control) — no gradient |

The gradient washes out at higher np: all four instances contend for the same N0 memory controller, so the nominally-local instance loses its advantage and queueing noise dominates (in `qwen3_next_80b-C1b-np4` the remote instance is even *faster*). That is expected under a single saturated controller and does not weaken the direct `numa_maps` evidence — but it does mean the per-instance gradient should be cited as corroboration, not as the primary proof.

### The instrument saw this and did not gate on it

In every affinity artifact the memory check records `required: false`, `match: null`, `note: "shared mmap placement observed"`. Per `affinity_preflight.py:195`, `required = no_mmap and len(expected_nodes) == 1` — the locality gate arms **only** for `--no-mmap` roles. E5 runs mmap'd (with `mlock: true`), so the gate never armed: the preflight measured a 0.0 `local_fraction` on six qwen36 cells and reported it as `not required`. `live_memory_placement_verified: true` in those artifacts means *the placement was observed*, not *the placement was correct*. Worth closing before the re-run.

### 6c. Re-run design notes (all three defects)

1. **Order or isolate the placement.** Because the shared GGUF page cache is placed once per run and inherited, a run's *first* cell dictates every later cell's memory locality. Either drop caches between placement shapes, or launch every instance under an explicit policy (`--interleave=all` for multi-node shapes, `--membind=<node>` for quarters) so placement is declared rather than inherited.
2. **Arm the locality gate for mmap roles.** `affinity_preflight.py:195` only arms it under `--no-mmap`. Under mmap it should still fail a single-node instance whose `local_fraction` is below threshold — this run had six cells at `local_fraction = 0.0` pass preflight.
3. **Size the prompt batch to the concurrency.** 43 pinned prompts cannot hold 32 slots occupied; the T>=16 rungs averaged well under half nominal occupancy.
4. **Keep both throughput fields and label them.** `aggregate_decode_tps` is per-slot; a system-wide decode rate (union-window) is what should be compared against `aggregate_wallclock_tps` and against `llama-bench` tg.

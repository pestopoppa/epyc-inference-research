# Same-attempt raw search window

This installed v2 prerequisite captures bounded original observations on the
existing parent evidence thread. It is not a competing executor, grant provider,
`WindowAttestations` issuer, scientific grader, or completed search-feedback path.
The default v1 worker/health request remains unchanged.

## Installed input and prospective binding

`search_window.InstalledSearchWindowConfiguration.from_dict` accepts one closed
JSON schema and returns immutable explicit configuration: original claim/proc/
CPU-sysfs/storage roots, CPU-region names, existing `HostStatePolicy`, storage
floor, finite observation budgets, optional explicit package-counter paths, and
the expected loaded source digest. Original serving-cell calibration and executed
control references are separate preparation dependencies. Their presence as
strings does not verify those outputs or confer their authority.

Pass the same configuration to `NativeFactualEvidenceConfiguration` and
`loaded_planned_serving_identity`/`seal_loaded_instrument` before the experiment
plan is issued. The child reconstructs this exact fixed type from the original
loaded-instrument artifact and reseals against actual loaded source. Missing,
changed, or incomplete identities refuse; no arbitrary import selector exists.
The combined acceptance packet includes the standalone v3 serializer and its
exact configured-service propagation; they remain distinct versioned contracts.

The source closure pins the actual marker emitter and checkpoint, inherited IPC
exchange, parent request/ACK cache, lifecycle transport dispatch, parent service
loop and hooks, raw reader/parsers, lifecycle interval reduction and original
preflight predicates. It does not merely attest a list of permitted marker names.
The existing loaded native producer closure continues to pin native joining and
replay. Model hashing/preparation belongs before the window-open hook; its owner
must preserve that ordering when composing the separate patches.

## Lifetime and bounds

The existing binding request supplies the original active-claim snapshot. The
parent opens raw host/claim/storage capture after preparation and before binding
ACK. Closed v2 warmup, measurement, measurement-end, and teardown messages join
the exact nonce, unit/process, fence, binding, descendant event, and monotonic
boundary. Health retains its original v1 request. Retries reuse exact immutable
messages; changed retry, backwards time, skipped predecessor, or unknown phase
refuses. An early exceptional teardown closes an incomplete window, never a valid
full window. Teardown obtains a fresh active-claim snapshot while still held.

The parent loop gives queued IPC priority, then advances one bounded observation
operation after each notice or timeout. Pending snapshots request a zero queue
timeout, avoiding a 50 ms sleep for every CPU file. No catch-up loop or background
mutable owner is introduced. Slow/final reads are checked against the original
sample deadline, including the final operation; a close cancels an unfinished
sample. Sample count, raw bytes, process/directory enumeration, total snapshot
bytes, cadence, and boundary time are finite. With v2's fixed five markers the
retained transport budget is exactly eight keys per unit: binding, descendant,
five markers, and artifact completion. Request/response caches share those keys.
Continuation remains unsupported for observation-bound v2.

Raw regular files use nonblocking, no-follow opens and bounded EOF reads (procfs
size zero is not evidence of emptiness). Original device/inode, process ancestry,
holder descriptions, timestamps, bytes, and errors are retained. The extracted
preflight parsers/reducer preserve the existing CPU/GPU unavailable, foreign,
OFD, owned-incomplete and empty-namespace policy. They perform no I/O during
captured reduction. `CapturedClaimWitness` is transient parser input, not an
authority token; retained owner facts are deep-frozen.

## Sealed factual result and replay

`SameAttemptWindowOwner.seal` joins the original native artifact, actual parent
factual result receipt and reopened lifecycle observation. It rederives the
existing lifecycle CPU/census/memory intervals and binds the exact parent phase
and measurement-end timestamps. Every receipt includes original artifact
references, source/configuration/plan identities, raw open/close and periodic
host observations, fresh close-claim result, and explicit preparation debt.
Owner-issued receipt capabilities can be reopened after service shutdown through
a fresh descriptor-bound `ArtifactStore`; frozen facts cannot be mutated.

Warmup and measurement process census, PID-start identity, CPU deltas, memory/
swap/PSI, target placement and memory mappings come from the existing lifecycle
sampler, not a duplicate broad census. Two actual during-phase reads and bounded
gaps are required for factual coverage. Intervals crossing a phase boundary are
retained separately and cannot establish a during-phase delta. Marker join and
phase coverage are separate checks; aggregate coverage requires both. Host
coverage requires two completed reads within the measurement bounds. Zero/short
windows and post-close samples remain unknown.

Foreign activity can be observed between otherwise quiet endpoints. The receipt
retains that activity and original census-change/pressure diagnostics. It never
infers build/model purpose from argv, treats one-minute load as instantaneous
contention evidence, or turns an empty overlap list into a clean-window proof.
Even observed factual coverage does not issue `no_concurrent_work`, correctness,
control/calibration, or a scientific search verdict. Original unit unknowns and
diagnostic arm carriers are not rewritten.

## Remaining owning composition

This packet does not construct full `api.WindowAttestations`. Binding explicit
CPU-region selection to installed claim scope, an actual GPU-claim witness,
under-load frequency/control/anchor/evaluator gates, and original serving-cell
calibration/controls must come from their actual owners. The next contained
producer must run the existing solve/control harness in the serving frame and
capture the original commitment, raw pools, control definitions/results and
source identity before candidate issue; a historical CPU-bench calibration or
floor-only receipt cannot substitute. The approved parent-final trial/T0 packet
and search attachment/reducer/feed/disposition consumer are separate remaining
work. `UnifiedDriverExecution._finish` still has its existing default-invalid
behavior until that genuine owning composition is connected.

## Acceptance boundaries

Tests run an actual owned non-kernel child and parent service through completion,
sealed receipts, native capture/replay and restart; fixture observations are
labelled synthetic and never an inference benchmark. Independent tests exercise
the actual parent polling loop at 48/96 declared CPUs with 0.2 ms synthetic read
latency, continuous IPC, final-read deadline overrun, original preflight/parser
equivalence, foreign activity present only between endpoints, cross-phase
intervals, and zero-duration/post-close refusal. These prove raw plumbing and
bounded factual reduction, not a positive all-witness scientific comparison.

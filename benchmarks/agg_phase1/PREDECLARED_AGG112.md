# AGG-1.12 predeclared - adopt `agg_pipeline.v2` and re-ingest the 28-document corpus, then re-answer the 58 questions

Written 2026-11-12 by the AGG-1.12 preparation session, before any AGG-1.12 model call. **This is post-hoc work on AGG-1.1 data
and says so.** The pipeline components were each chosen after reading the AGG-1.8 miss table, the AGG-1.11 triage and the AGG-1.6
A/B, all of which are about THESE 28 documents, these 211 gold cells and these 58 questions. There is no untouched evidence for any
gain claimed below (the out-of-sample section says exactly what can and cannot be measured). It sits beside `PREDECLARED.md`
(AGG-1.1, sha256 `2d4a532197ec316d253b9009646be6586cc0a0b4db639daf2e7a0af0af4b78af`, not edited) and imports its frozen
questions, golds, deterministic scorer, metric definitions and the Phase 0 kill bounds unchanged. Its own sha256 is recorded in
the compute rows, the jobs' `precond.sh` and the runner (`run_agg112.py` / `agg112.py`).

## Question

Box AGG-1.12 (`handoffs/active/knowledge-pipelines.md`, root `dcd9c30d2`): with typed L4 extraction over union windows (AGG-1.6 arm
T), `l3_period.v2` and `canonical.v2` attributable net income made ONE pipeline version, `agg_pipeline.v2`, and the full 28-document
L4 ingest and the 58-question P-large answer set re-run under it, what are M1 and P-large accuracy against AGG-1.1 (0.877 and
0.310), are M3 and M4 inside the Phase 0 bounds, and does any previously correct cell regress?

Scope: Qwen3.6-35B-A3B-MTP Q8_0 on the v10 production CPU kernel store (CPU quarter) for ingest; Qwen3.8-27B Q8_0 + DFlash2 on the
MI210 (v10 GPU kernel store) for the L4c audit and the answers. It concludes nothing about other corpora, other models, other
questions or other fiscal years.

## Pipeline versions (reproducibility of Phase 0 and AGG-1.1)

`agg_pipeline.v1` is the default of the orchestrator (`src/aggregation/pipeline.py`, env `ORCHESTRATOR_AGG_PIPELINE`, unknown values
refused) and calls every stage with the exact legacy arguments: Phase 0 and AGG-1.1 reproduce byte for byte, and the orchestrator
tests assert it (v1 L3 equals the legacy call, v1 canonical equals the default call, `facts_llm.py` keeps sha256
`c64b7c9ed7df88906d38f07e71c5605bcbb4aae66549452ae42487c257dd7451`, the registry's default build is unchanged). `agg_pipeline.v2`
(orchestrator commit `4d0265cdd3fad52a23b26050924dded38f27b514`, built on `749afcd0e` l3_period.v2, `6ec701df` canonical.v2 and
`1a408ce4` unit cross-check):

| stage | v1 | v2 |
|---|---|---|
| L3 period | legacy (`period_version=None`) | `l3_period.v2`, default components (table_split, table_header_narrow, first_column, row_select), the filing's fiscal year from the corpus manifest |
| L4 | `facts_llm` rows: top-6 windows per (field, document), admission gate, one call per admitted window and field, `n_predict` 256 | `facts_typed` (`l4_typed.v1`): per (field, document) the UNION of the current top-6 and a field-specific top-3 windows (`FIELD_QUERY`), no admission gate; ONE typed multi-field call per DISTINCT window of the document (9 slots: the 8 schema fields + long_term_debt; at most 2 rows per slot; quote <= 100 characters; `n_predict` 1024); each window's rows kept only for the fields that chose that window; unchanged `facts_llm.extract` / `reconcile` |
| canonical | `canonical.v1` | `canonical.v2` with the `attributable_net_income` guard only |

Not adopted, on measured evidence: the canonical thousands-unit guard (0 fixes, 0 breaks), the l3_period optional components
(`inline_header` breaks PFIZER net income; `date_header` breaks AMD revenue), the AGG-1.6 arm C1 (0 of 5 on the pilot). The per-document
fiscal-year and unit-label fixes (`1a408ce4`: `declared_scale`, `unit_override`) are in `facts_llm` itself and are ON for both
versions. The 9th slot (long_term_debt) is asked because arm T asked it, but no (long_term_debt, document) unit exists, so its rows are
dropped by the slot gate: the schema stays the AGG-1.1 eight fields. A zero-compute check in preflight asserts that the
orchestrator stage equals the AGG-1.6 arm T code (field queries, grammar, prompt, union windows, constants); a mismatch fails preflight.

## Procedure

1. Preflight (zero compute): pins, frozen inputs, the stage-equals-arm-T check, the offline window plan and its M3 projection.
2. L3 (no model): a COPY of the AGG-1.1 store (never mutated), every fact and everything derived from facts wiped, L3 re-extracted under
   `l3_period.v2`. The document parse (documents, chunks, tables, pages) is NOT repeated: it does not depend on the pipeline version.
3. L4 (CPU quarter, one private server, the AGG-1.1 recipe): pilot on MICROSOFT, JOHNSON_JOHNSON, 3M; then the other 25 documents by
   ascending extracted size; one unit per window call, fsynced, resumable. **L4 reuse: none.** Every one of the 224 (field, document)
   units is a fresh typed L4: the v2 stage is not identical to any AGG-1.1 or Phase 0 unit, so no unit is a cache hit.
4. Final look: M1 (raw and canonical), M3, regressions and strata, `result.cpu.json`. The CPU store is written with `canonical.v2`.
5. GPU (after the CPU result passes): the L4c audit sample (the AGG-1.1 recipe, unmodified), then P-large on the 58 under planner
   `agg110.v1` (primary) and again under `agg11.v0`, on the same store. No B1, P-small, B-today or B2. The two passes separate the planner
   effect (agg110.v1 vs agg11.v0 on the v2 store) from the pipeline effect (v2 store with agg11.v0 vs AGG-1.1).

## Gates

Pilot (3 documents, <= 1,800 s), **futility-only**: stop (`phase1_gate_tripped`, the GPU window is never requested) if the pilot M1
(raw, the pilot documents' 24 cells, all facts: v2 L3 plus typed L4) is below AGG-1.1's on the SAME cells (20 of 24), or the projected
M3 is over a kill bound. Budget stops (re-book, NOT gates, exit 5): pilot wall > 1,800 s; projected L4 wall > 2x the booked 9,000 s; later,
fresh L4 wall > 1.5x the pilot projection. Interim look after 14 documents: futility only (raw M1 on the completed documents' cells below
AGG-1.1's on the same cells, or the running M3 over a kill bound); never an early GO.

Final, CPU row: **M3 inside the Phase 0 kill bounds** (prefill / corpus tokens <= 2.0, calls per 100 chunks <= 150); **M1 (raw) >= AGG-1.1's
185 of 211**. A failure files `phase1_gate_tripped` naming the gate and the GPU row never runs. The GPU precondition (`cpu_ready`) is
exactly: complete, no futility stop, no gate tripped, M1 found >= 185, M3 passed. Regressions do NOT block the GPU row (the P-large
numbers are worth having either way) and are decided in the verdict.

Final, GPU row: **M4 inside bounds for BOTH planners**: median calls <= 3 and median prefill <= 2,510 over the 58 (the Phase 0 values 2 / 510
plus 1 call and 2,000 tokens; kill 8 calls). Verdict, mechanical:

* `phase1_gate_tripped` naming the gate (M1, M3, M4:agg110.v1, M4:agg11.v0);
* `agg_1_12_not_met` when the gates hold but a cell that was right in AGG-1.1 (raw M1 or canonical.v1) is not right now (listed, with its stratum);
* `agg_1_12_done` when the gates hold and no previously correct cell regressed. The numbers are FILED against AGG-1.1 in every case.

P-large accuracy is filed against AGG-1.1 (18 of 58) for both planners with a paired exact comparison (b = only new right, c = only AGG-1.1
right, z = (b - c) / sqrt(b + c)). It is **not a gate**: the box's DONE WHEN is "filed against AGG-1.1 with M3 and M4 inside the bounds and no
previously correct cell regressing". The result also carries `adopt_agg_pipeline_v2_as_default` = no gate tripped, no regression, M1 not down and
primary P-large not down; that is a recommendation for the owner, not a mechanical act, and it is IN-SAMPLE.

## Expected effect versus the sampling error (stated before the data)

* **M1, in-sample.** The 26 never-extracted cells are the headroom (AGG-1.1 missed exactly those 26 on raw M1). Arm T filled 35 of the 38
  target cells (all 14 primary FORMAT, 10 of 13 RETRIEVAL, 11 of 11 L3-class under l3_period.v2 on its own: 8 of 11) and l3_period.v2 added 7
  fixes with 0 breaks on a copy of the AGG-1.1 store. Expected: raw M1 +18 to +26 cells, i.e. 203 to 211 of 211 (0.96 to 1.00); canonical
  177 -> about 195 to 205. A sign test on the discordant cells (b about 22 fixes, c 0 to 2 breaks) gives z about 4.1 to 4.7; the unpaired
  binomial SE of an M1 near 0.95 over 211 cells is 0.015, so a +0.10 move is about 6 SE. The pilot (24 cells, AGG-1.1 20) has a binomial SE
  of about 0.076: it screens for a pipeline defect, it does not estimate the gain, and it trips only on a result below 20.
* **P-large, in-sample.** AGG-1.8 re-scored the 14 saved store-gap SQLs on gold-corrected cells and all 14 flipped (32 of 58 = 0.55 on saved
  plans); AGG-1.10 fixed 8 of 26 plan/SQL misses on the old store (8 of 9 of its ceiling). A perfect store with the new planner would sit near
  40 of 58 (0.69). Expected: agg110.v1 29 to 40 of 58 (0.50 to 0.69), agg11.v0 23 to 32 (0.40 to 0.55). The binomial SE of a 58-question
  accuracy near 0.5 is 0.066; the paired z for b about 18 and c about 1 to 3 is about 3.6. The smallest paired effect that would clear z = 2 is
  b = 8 with c = 0 (z 2.8); b = 5, c = 2 (z 1.1) is indistinguishable from noise, and a gain of that size would be reported as such.
* **No regression, with its real strength.** 185 cells were right in AGG-1.1. Observing 0 breaks bounds the per-cell break rate at 1.6% (one-sided
  95%); a true 1% rate would still leave 16% probability of 0 breaks. Arm T saw 0 breaks on 70 non-target cells touched (bound 4.2%). "No
  regression" is a point check on these cells, not a certificate of a rate.
* **Determinism.** temperature 0, top_k 1, seed 0, thinking off, `-np 2` on CPU: records are reproducible per call on the same binary, but
  batching can change the bytes of a reply; a difference of one or two cells between a re-run and this run is within that.

## Out-of-sample: what can be measured, by script from the committed files

Option (a), a held-out evaluation on cells never inspected while the AGG-1.8 / 1.11 / 1.6 designs were made. `agg112_reference.json`
(`partition`) lists, by script and with the reason per cell, the cells NAMED in a design artifact: the 26 AGG-1.9 / AGG-1.11 triage cells (which
include the 38-cell arm-T target list's 211-cell members and the 11 L3-class cells), the AGG-1.8 bad cells (26 never extracted correctly, 8
canonicalisation misses, 1 spurious), and the 26 cells named in the AGG-1.8 blanket tier probe (7 fixed, 19 broken): **53 of the 211 are TOUCHED,
158 are HELD-OUT**. Cells only counted in aggregate by the retrieval probe (gold window held in 206 of 211), the l3_period variant table and
the canonical guard probe are not touched by this definition; they are weakly in-sample for the component choices and are labelled so.

What this partition can and cannot say, fixed here:

* On the 158 held-out cells AGG-1.1 was already right on **158 of 158 (raw) and 158 of 158 (canonical.v1)**; the 26 raw misses and the 8
  canonical misses are all among the 53 touched cells. The held-out set has no headroom: it can show a REGRESSION, never a gain. Its
  figure is a regression test: 0 breaks bound the per-cell break rate at 1.9% (one-sided 95%).
* **No question is held out.** Every one of the 58 questions reads between 2 and 17 touched cells (0 of 58 read only untouched cells), and all 58 were
  seen in the AGG-1.8 miss table. P-large accuracy is IN-SAMPLE for any gain. There is no held-out P-large figure and none is invented.
* Therefore M1 and P-large are reported with their labels: **IN-SAMPLE** (all 211 cells, the 53 touched cells, all 58 questions) and
  **HELD-OUT (regression test only)** (the 158 cells: raw and canonical M1, fixed and broken lists). Neither is called out-of-sample evidence of
  improvement.

Option (b), new golds on new FinanceBench filings, is the only way to an out-of-sample gain, and it is NOT run here: to see a gain of the size
expected (a discordance of about 9% of cells, +7 points) with z >= 2.5 it needs about 115 new cells (about 15 filings of 8 cells), which is the
cost of the AGG-1.1 step A corpus (18 filings, 144 cells) and needs new questions for P-large. Four filings (32 cells) would give z about 1.3 and
could only show a large effect or a defect. Filed as a follow-up proposal, not as a part of this PREDECLARED.

## Post-hoc caveats (all of them stand in the verdict)

1. In-sample: the design (windows, field queries, slots, guards, component choice among 9 l3_period variants) came from these cells; M1 and P-large
   gains are not estimates for unseen filings. The 158 held-out cells are a regression test, not a validation.
2. The 144 non-Phase-0 gold cells have one reader plus a cross-extractor check (PREDECLARED.md caveat 3); the 20 continuity questions were
   re-evaluated over 28 documents.
3. The AGG-1.1 comparator is a saved run (2026-11-11) on the same model, kernel and recipes; a re-run of the v1 pipeline today was not made, so
   run-to-run variation of v1 is unmeasured. Reuse of Phase 0 L4 units in AGG-1.1 means part of its M3 is a Phase 0 measurement.
4. The pipeline effect and the planner effect are separated only on the v2 store (agg110.v1 vs agg11.v0); agg110.v1 on the v1 store was run on
   26 of the 58 questions (AGG-1.10), not all 58.
5. The slot gate (a window's rows count only for the fields that chose it) is a design choice made to keep a (field, document) unit's facts the
   same kind of object as v1's; arm T itself kept all slots of a cell's windows. It was not tuned on outcomes.
6. M3 here counts typed window calls (one call per distinct window); a v1 unit counted one call per admitted window and field. The bounds are the
   same numbers; the units of count differ, so the calls-per-unit figure (903 / 224) is a derived quantity.
7. Gate classes are futility-only at the interim looks until OP-ABSEQ / OP-PQP / OP-ALPHAWIN are decided; no early GO is possible.
8. Estimates below are ESTIMATES from measured rates, not measurements.

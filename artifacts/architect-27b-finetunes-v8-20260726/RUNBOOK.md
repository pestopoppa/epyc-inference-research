# 27B finetune observation runbook

1. After MiniCPM-o M1 and M2 are complete, run `python3 -B finetune_bench_runner.py --preflight --validate-gguf`. This verifies v8, immutable prompts, all model/component hashes, evaluator Python/SWE-bench identity, Docker identity, and the Fable GGUF tensor contract. It starts no process and writes nothing.
2. Render one exact recipe with `--dry-run --recipe-id OBS-27B-V8-NOSPEC-v1` or `OBS-27B-V8-FABLE-EMBEDDED-MTP-v1`. The render is the authority for the exact arms, request fields, input hashes, and server argv. The normal quality recipe is deliberately no-speculative-decoding.
3. Do not use `--execute` until the reviewed generic M1-derived ownership backend is integrated. That backend must own a fresh server process group, refuse an occupied port, record pid/start-ticks/listener/GPU/ROCm/runtime libraries, wait for readiness, seal one raw response record per fixed item, and prove postflight process/GPU cleanup.
4. The backend must use the rendered `v7_quality_gate_runner.py` request path. Recompute LCB code execution from sealed raw JSONL. For SWE, run the pinned `convert_sr_to_patch.py` then the pinned `swebench.harness.run_evaluation`; no-patch, timeout/error, and truncation remain failures in /40 or /53. Create a new contained run directory; never overwrite or resume anything except sealed complete per-item records.
5. ThinkingCap-on vs stock-off is a different-model quality-plus-token-cost contrast. Record prompt/generated/completion/reasoning/accepted tokens. Fable non-MTP vs stock non-MTP is quality only. Fable embedded-MTP vs non-MTP is MTP impact only. External stock MTP is excluded pending its separate load-only MI210 residency gate.

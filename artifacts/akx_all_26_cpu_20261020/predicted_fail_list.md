## Reading the table
- Contract: batched op with k columns/queries (ne11 / Q->ne[1] / n_tokens = k, k = 1..9) vs k serial single-column ops on the same operands, memcmp, tolerance 0.
  k=1 is the identical op and is trivially PASS. "FAIL@k=N" = the first width N whose batched output is predicted NOT to equal the serial reference; every width below N is predicted bit-equal.
- "inference" (column "conf") = the verdict is NOT a pure source-level routing fact: it rests on a floating-point-association argument, an occupancy/env/routing assumption, or an unread helper. Route-switch FAILs (different kernel family at width N) are source facts about routing; "the two kernels differ in the last bits on real data" is the (near-certain) inference attached to them.
- Paths are relative to the tree root; short names: `ggml-cuda.cu mmvq.cu mmq.cu mmq.cuh mmf.cu fattn*.cu* gated_delta_net.cu` = `ggml/src/ggml-cuda/`, `ggml-cpu.c ops.cpp common.h` = `ggml/src/ggml-cpu/`, `sgemm.cpp` = `ggml/src/ggml-cpu/llamafile/`, `iqk_*.cpp` = `ggml/src/ggml-cpu/iqk/`, `quants.c` = `ggml/src/ggml-cpu/arch/x86/quants.c`, `delta-net-base.cpp llama-context.cpp` = `src/models/` and `src/`.

What the surface says

rankingA4 ≫ A3 > A1, everywhere batched

At every batched operating point the order holds. L=2k peaks: 243 / 153 / 103. The small-active MoE wins on both fronts — fewest active params and clean scaling.

correctionThe dip & collapse are A1-specific

Earlier I called the np=2 dip "MoE-specific" and long-CoT batching "collapsing." Both were over-generalized from A1. A4 (also MoE) shows no dip (1.43× at np=2) and batches fine at 32k. A1 alone collapses — confounded across IQ2 / MTP-2 / large-active; cause not yet isolated.

mechanismWhy dense batches so well

Dense amortizes weights across the batch — read the 27 GB once, apply to all np tokens. MoE tokens scatter to different experts, so its fewer-active-params edge only pays at high np with expert reuse — exactly why A4 climbs to np=32 while A3 plateaus at np=8.

caveatnp=1 baselines are noisy

Each cell runs one wave (NREQ=np), so np=1 is an n=1 sample (A4 ranged 72–99 across L). The batched aggregates (n=np) are the reliable reads — policy is set from peaks, not np=1 ratios.

scopeThroughput ≠ quality — this is a tiebreaker, not a verdict

Reasoning accuracy was a well-powered NULL across A1/A3/A4 in the architect bench (six suites). So throughput is a legitimate tiebreaker — and on GPU it favors A4, then A3 — but the architect decision also weighs deployment robustness and the 122B's dual-residency. This surface informs where and how each arm runs, not which is "smarter."

Router-integration plan
◧ GATED

The MI210 is today a bench instrument, not a serving node — production is CPU-only. This plan activates only when the GPU is registered as a serving backend in orchestrator_stack.py / model_registry — an operator-gated stack change. Until then it's a parameterization staged and ready.

LAYER 1 · launch-time

Static server sizing

Size each model's launch -np to its expected budget distribution (from AutoPilot's realized token stats). Short-budget roles → high np; deep-reasoning architect → low np. Never launch A1 at np=2.

LAYER 2 · request-time

Budget → concurrency co-decision

Extend the learned router to emit a concurrency ceiling alongside the budget it already picks. Don't admit a request into a slot pool that would exceed np_ceiling(budget) for that arm.

LAYER 3 · live

Admission & placement

Track Σ(budget·kv/token) against both the VRAM cap and the bandwidth-collapse ceiling. Near the edge, admit / queue / downgrade — or route to CPU — rather than pack another slot into the collapse region.
